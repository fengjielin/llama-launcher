# 05 参数拼装与决策表

> **本章目标**：说清「界面上的一个值怎么变成命令行里的一个参数」，以及为什么有些值**故意不传**。
> **主要文件**：`src/core/args.ts`（900 行）、`src/core/schema.ts`（359 行）、`src/test/args.test.ts`（400 行）。
> **前置**：[04 环境探测与预检](./04-环境探测与预检.md)。

## 0. 学完这章你能回答什么

- `buildArgs()` 为什么必须是纯函数？「预加载模型路径」「preset 文件路径」是谁算出来的？
- 我配了 `context: 16384`，为什么命令行里**没有** `-c`？—— `presetOwns` 与 `presetKeys` 的**并集**策略。
- 为什么预加载的模型反过来**必须**直传 `-c` / `-n`？「加了 `n-predict` 反而让 `-n` 消失」是怎么修的？
- 决策表那七种原因（`cli` / `preload-override` / `preset-owned` / `unsupported` / `fallback` / `skipped` / `unset`）各是什么意思？
- 版本不认识某个参数时，为什么敢「什么都不传」？`--fit-target` 退回 `-ngl 99` 为什么不算「静默降级」？

## 1. 先看问题

前四章铺垫了输入：归一化的配置（03 章）+「当前版本认哪些参数」的能力视图（04 章）。现在要把它们变成一条真命令行：

```bash
llama-server.exe --host 127.0.0.1 --port 8080 -m E:\Code\llama\models\qwen2.5-7b-instruct-q4_k_m.gguf -t 6 -c 16384 -n 8192 -fa on
```

看起来直白 —— 配置里有 `context: 16384` 就传 `-c 16384`。但有三种麻烦会让用户问「我明明配了为什么没生效」：

1. **preset 会吃掉参数。** router 模式下你给每个模型写了预设，而实测 llama.cpp 里**命令行优先级高于 preset** —— 命令行再传一遍 `-c` 就会盖掉预设。所以「preset 里定义过的键，命令行不能再传」。
2. **预加载的模型又不吃 preset。** 启动即加载的那个模型 preset 对它不生效（实测 ctx 被忽略、`--fit` 还会把 ctx 压到 4096），这些参数必须**反过来直传**。项目真踩过：预设里一写 `n-predict`，`-n` 就被判成「preset 接管」而**不传**了（`README.md:170-172`）。
3. **参数名会改。** `-fa` 在新版是 `-fa on/off/auto`、旧版是纯开关；`--draft-type-k` 改成了 `--spec-draft-type-k`。硬编码名字的启动器会在某个版本上崩掉。

`src/core/args.ts` 就是回答这三个问题的：纯函数 `buildArgs(input)` 输出「argv + 环境变量 + 逐参数决策记录 + 告警」，那份记录就是界面上的**决策表**。

## 2. 核心概念

### 2.1 纯函数：不读文件、不探测、不猜

```ts
// src/core/args.ts:186-188
 * 这是整个 core 的核心，且是**纯函数**：不读文件、不起进程、不访问网络，
 * 因此同一份配置在任何环境下都会得到同一条命令行（GUI 与 CLI 靠这一点保持一致），
 * 也正因如此才能用单测逐字节对拍。
```

拼命令行天然需要外部事实（预加载模型的绝对路径、渲染好的 preset 路径），项目把**文件操作全部推给调用方**，用 `BuildInput` 字段送进来 —— 例如 `presetArgPath` 的注释就写着「调用方负责把它渲染成 ini 写到临时文件，再把那个路径放这里 —— `buildArgs` 本身不做文件操作，保持纯函数」（`src/core/types.ts:296-302`）。调用方是编排层 `prepareLaunch`（`src/core/launcher.ts:289-299`）。于是「编排」与「判定规则」各自可单测，GUI 与 CLI 走同一条链路。

### 2.2 `emit`：所有参数走同一条判定流水线

40 多个参数若各写一套 if，判定顺序必然分叉。内部只有一个 `emit`，每个参数只给它一组选项（`EmitOptions`，`src/core/args.ts:165-181`），顺序被写死：

```ts
// src/core/args.ts:190-197
 * 每个参数的处理都遵循同一套判定顺序（由内部的 `emit` 实现）：
 * 1. 值为 `undefined`/`null`/空串 → 记 `unset`，**不传给 llama.cpp**（用它的默认值）
 * 2. `skipWhen` 判定为"无需传"（如 `-1` 表示自动）→ 记 `skipped`
 * 3. presets.ini 里定义过同名键 → 记 `preset-owned`，命令行**不传**
 *    （实测命令行优先级更高，传了会盖掉 preset）；
 *    例外：预加载的模型不吃 preset，此时改由命令行直传，记 `preload-override`
 * 4. 候选参数名在当前版本一个都不存在 → 记 `unsupported` 并告警，绝不硬传
 * 5. 否则按 `render` 决定"带值还是纯开关"，追加进 argv，记 `cli`
```

> 注释里的 `presets.ini` 是**历史措辞**：06 章会讲，预设现在写在配置的 `presets` 字段里、渲染成临时 ini 再传路径，但这条规则没变。

判定结果统一记成 `BuildStep`：`key` / `label` / `argv`（**这个参数贡献的那一段**，不是整条命令）/ `reason` / `reasonLabel` / `note`（`src/core/types.ts:259-266`）。返回值就是 `{ argv, env, steps, warnings }`（`src/core/types.ts:313-318`）。

### 2.3 `presetKeys` 是「所有模型段键名的并集」

判断「preset 是否接管某键」本该先回答「是哪个模型的 preset」，而 router 模式下当前模型运行时可切。项目的默认策略是**不看当前模型**：

```ts
// src/core/presets.ts:118-125
export function collectPresetKeys(file: PresetFile): string[] {
  const keys = new Set<string>();
  for (const [name, map] of file.sections) {
    if (name === "defaults") continue;
    for (const k of map.keys()) keys.add(k);
  }
  return [...keys];
}
```

理由是与旧的一键启动脚本行为一致 —— `src/core/presets.ts:108-111`：「只要【任意】模型段定义了某个键，命令行就不再传这个参数」，更精确的 `presetKeysForModel`（`src/core/presets.ts:134-137`）**存在但没被用作默认策略**，这是有意的兼容取舍。

### 2.4 `preloadBypass`：预加载模型的例外通道

```ts
// src/core/args.ts:172-173
  /** 预加载模式下允许绕过 preset 占位（实测预加载的模型不吃 preset） */
  preloadBypass?: boolean;
```

它标在 `threads`、`context`、`max_predict`、`kv_k_type`、`kv_v_type`、`gpu_layers`、`fit_target`、`load_mode` 上；采样参数（`temperature` 等）**没有**标，预加载时仍交给 preset。

### 2.5 七档 `StepReason` 与「文案只有一份」

```ts
// src/core/args.ts:83-91
const REASON_LABEL: Record<StepReason, string> = {
  cli: "命令行直传",
  "preload-override": "预加载直传",
  "preset-owned": "preset 接管",
  unsupported: "版本不支持",
  fallback: "兼容回退",
  skipped: "按规则跳过",
  unset: "未配置",
};
```

枚举含义在 `src/core/types.ts:242-256`。文案放 core 的理由（`src/core/args.ts:96-97`）：GUI 通过 IPC 拿数据、CLI 直接调用，**统一在这里提供**（随 `reasonLabel` 下发），避免两边各写一份后漂移。所以渲染层不认识英文枚举，只显示 `step.reasonLabel`（`src/renderer/src/components/DecisionTable.tsx:60`）。

## 3. 代码怎么走

### 3.1 `emit` 的判定：`unset` / `skipped` / `preset-owned`

第一步、第二步都不传参：值 `undefined`/`null`/空串记 `unset`（`src/core/args.ts:234-238`）；`skipWhen` 返回非空说明时记 `skipped`（`src/core/args.ts:240-246`）。第三步是本章的主角：

```ts
// src/core/args.ts:248-258
    const owned = presetOwns(opts.presetKey);
    if (owned && !(opts.preloadBypass === true && isPreload)) {
      steps.push({
        key,
        label,
        argv: [],
        reason: "preset-owned",
        note: `配置里的预设为某个模型定义了 ${opts.presetKey}，命令行不重复传（实测命令行优先级更高，会盖掉 preset）`,
      });
      return;
    }
```

`owned && !(opts.preloadBypass === true && isPreload)` 就是全部秘密：被 preset 接管了，但当前是预加载**且**该参数标了 `preloadBypass`，就继续往下走到命令行。第四、五步：

```ts
// src/core/args.ts:260-276
    const flag = caps.pick(candidates);
    if (flag === null) {
      steps.push({
        key,
        label,
        argv: [],
        reason: "unsupported",
        note: `当前 llama.cpp 版本没有这些参数：${candidates.join(" / ")}`,
      });
      warnings.push(`${label}：当前版本不支持 ${candidates.join(" / ")}，已跳过`);
      return;
    }

    const rendered = opts.render ? opts.render(flag, value) : String(value);
    const part = rendered === null ? [flag] : [flag, rendered];
    const reason: StepReason = opts.reasonOverride ?? (owned ? "preload-override" : "cli");
    argv.push(...part);
```

注意 `reason` 的三优先级：`reasonOverride`（回退专用）> `owned` 为真时的 `preload-override` > `cli`。另外 `emit` 的最后一步是 `if (opts.warning) warnings.push(opts.warning);`（`src/core/args.ts:288`），回退类改动必须同时留下告警。

### 3.2 机制一：preset 接管（`-c` 为什么消失）

键集合由编排层算好送进来：

```ts
// src/core/launcher.ts:292
    presetKeys: presetFile !== null ? collectPresetKeys(presetFile) : [],
```

于是只要**任意**模型段写过 `ctx-size`，`presetOwns("ctx-size")` 为真，`-c` 就不进 argv，决策表那行变成「preset 接管」并在 `note` 里带出键名（3.1 的片段）。这就是配了 16384 却没有 `-c` 的原因 —— 不是丢了，是**交接给服务器按模型读预设**了。`src/core/args.ts:215` 会把所有键小写化，`presetOwns`（`src/core/args.ts:220-221`）也小写化再比，所以 preset 里写 `Ctx-Size` 同样命中。

### 3.3 机制二：`preloadBypass`（`-c` / `-n` 反过来必须直传）

```ts
// src/core/args.ts:390-401
  const ctxFromPreset = input.preloadCtxFromPreset ?? null;
  const ctxValue = isPreload && ctxFromPreset !== null ? ctxFromPreset : config.context;
  emit({
    key: "context",
    label: "上下文长度",
    candidates: ["-c", "--ctx-size"],
    presetKey: "ctx-size",
    preloadBypass: true,
    value: ctxValue,
    note:
      isPreload && ctxFromPreset !== null
        ? `预加载模型不吃 preset，ctx 必须 CLI 直传（取自配置预设里的 ctx-size = ${ctxFromPreset}）`
```

值是 `ctxValue` 而非 `config.context`：预加载时**优先取该模型 preset 里的 `ctx-size`**，没有才回落配置级。这个值由编排层读出（`src/core/launcher.ts:262-267`），注释写明原因：「预加载的模型不吃 preset（实测 ctx 被忽略、fit 会把 ctx 压小），所以这两项要从它的预设里读出来、改由命令行直传」。

`-n` 是同一套机制，但它是**改出来的**（`src/core/args.ts:424-440`）：原来没有 `preloadBypass`，预设里一写 `n-predict`，预加载模型就被判成 preset 接管而不传 `-n`，于是它按 llama.cpp 默认的「无限」跑。

```ts
// src/core/args.ts:427-435
  const nPredictFromPreset = input.preloadMaxPredictFromPreset ?? null;
  const nPredictValue = isPreload && nPredictFromPreset !== null ? nPredictFromPreset : config.max_predict;
  emit({
    key: "max_predict",
    label: "单次生成上限",
    candidates: ["-n", "--predict", "--n-predict"],
    presetKey: "n-predict",
    preloadBypass: true,
    value: nPredictValue,
```

`preloadBypass: true` +「值优先取该模型的 `n-predict`」两件事合起来，才既保住 `-n` 的存在、又保住「按模型给推荐值」的语义。回归记录见 `README.md:170-172`（第 4 节完整引用），三种情形都被单测钉住（`src/test/args.test.ts:55-85`）。

### 3.4 机制三：版本不支持（候选名一个都没命中）

参数名一律走 `caps.pick`，它「按优先级返回第一个存在者，都不存在返回 `null`」（`src/core/helpProbe.ts:265-270`）：

```ts
// src/core/helpProbe.ts:265-270
    pick(candidates) {
      for (const c of candidates) {
        if (model.byFlag.has(c)) return c;
      }
      return null;
    },
```

返回 `null` 时 `emit` 做三件事（3.1 第二段片段）：记一条 `unsupported`、push 一条告警、**不往 argv 写任何东西**。原则是 `src/core/args.ts:7-8`：「参数名一律走 `caps.pick(candidates)`，版本不支持就走回退分支或明确告警，绝不静默变成一个语义完全不同的启动方式」。所以界面上不是「参数没了」，而是决策表一行「版本不支持」+ 顶部告警。草稿参数的改名把这条路径用得很足，候选名同时列新旧两套（`src/core/args.ts:856-875`）。

### 3.5 兼容回退：没有 `--fit-target` 就退回 `-ngl 99`

显存分层是三分支级联（`src/core/args.ts:669-719`）：**给了数字** → 传 `-ngl`；否则**版本有 `--fit-target`** → 交给 `--fit` 自动算；否则**不是纯 CPU** → 回退并告警：

```ts
// src/core/args.ts:699-710
  } else if (input.cpuOnly !== true) {
    emit({
      key: "gpu_layers",
      label: "显存分层数",
      candidates: nglCandidates,
      presetKey: "n-gpu-layers",
      preloadBypass: true,
      value: 99,
      reasonOverride: "fallback",
      note: "本版本没有 --fit-target，退回 -ngl 99（全量 offload），避免静默变成纯 CPU 推理",
      warning: "当前 llama.cpp 版本不支持 --fit-target，已回退 -ngl 99（全量 offload）",
    });
```

`reasonOverride: "fallback"` 让决策表一眼看出「这不是你配的，是降级来的」；纯 CPU 场景走最后的 `else`，只记 `skipped` +「纯 CPU 模式，不做 GPU offload」（`src/core/args.ts:711-718`），因为此时退 `-ngl 99` 是错的。**另一条回退**是「新参数不在就退回旧参数」，值只能丢（旧参数是纯开关）：`--load-mode` 不在时用 `--mlock`（`src/core/args.ts:735-747`），同样带 `reasonOverride: "fallback"` 与 `warning`，并靠 `render: () => null` 只传开关名 —— `render` 返回 `null` 表示「只传开关名」、返回字符串表示「传值」（`src/core/args.ts:174-175`）。思考模式回退更复杂：旧版退到「`--reasoning-budget` + 环境变量」双管齐下（`src/core/args.ts:554-598`），环境变量名是导出的常量 `CHAT_TEMPLATE_KWARGS_ENV`（`src/core/args.ts:26`），并且会**额外**记一条 `key: "think_env"` 的决策行（`src/core/args.ts:589-597`），让界面上能看见环境变量也参与了启动。

### 3.6 值类型：数字、字符串、布尔开关，以及「开关的反面」

去掉 `render` 时值是 `String(value)` 直接拼（`src/core/args.ts:273`）。第一处要特殊处理的是**默认「开」的布尔参数：「关闭」必须显式表达**（`src/core/args.ts:445-446`：「悄悄不传等于没关 —— 这是界面把三态参数做成开关后最容易出的错」）。Flash Attention 按 help 探测结果选形态：

```ts
// src/core/args.ts:447-459
  const faFlag = caps.pick(["-fa", "--flash-attn"]);
  if (faFlag !== null && caps.hasValue(faFlag)) {
    emit({
      key: "flash_attention",
      label: "Flash Attention",
      candidates: ["-fa", "--flash-attn"],
      presetKey: "flash-attn",
      value: config.flash_attention === null || config.flash_attention === undefined
        ? null
        : config.flash_attention
          ? "on"
          : "off",
      note: "本版本是 -fa on/off/auto 的新语法，关闭会显式传 off",
```

依据就是 `--help` 的占位符本身，`fixtures/help-b10488.txt:39` 那行长这样：

```text
-fa,   --flash-attn [on|off|auto]       set Flash Attention use ('on', 'off', or 'auto', default: 'auto')
```

旧版没有占位符时走 `else` 分支：`skipWhen` 把「关掉」标成「无法显式关闭，只能不传」，并用 `render: () => null` 保证只传开关名（`src/core/args.ts:461-471`）。第二处是**默认开启、靠 `--no-xxx` 关闭**的参数，走另一条路径（要选的是反向参数名），例如 `--jinja`（`src/core/args.ts:496-517`）：`config.jinja === false` 时优先 `caps.pick(["--no-jinja"])`，没有就如实报 `unsupported` + 告警「无法关闭，将保持默认启用」。第三处是**值是布尔、正式形态要带固定字符串**的，用 `render` 返回常量：`--tools` 的 help 要求 `specify "all" to enable all tools`（`fixtures/help-b10488.txt:510`），于是 `render: () => "all"`（`src/core/args.ts:841`）；`--agent` 允许纯开关，就用 `render: (flag) => (caps.hasValue(flag) ? "on" : null)`（`src/core/args.ts:850`）。还有一个「值语义」处理：`rope_scaling` 未开启时，`rope_scale` 与 `yarn_orig_ctx` 整体记 `skipped`（`src/core/args.ts:405-422`）。

### 3.7 `enumValues`：下拉框，不是校验器

```ts
// src/core/schema.ts:266-270
    label: "思考模式",
    group: "reasoning",
    kind: "enum",
    candidates: ["--reasoning"],
    enumValues: ["on", "off", "auto"],
```

它经 `buildSchemaPayload` 送到渲染层（`src/main/payload.ts:64`），在 `ParamsForm` 里变成下拉框外加一个「（用 llama.cpp 默认）」空选项（`src/renderer/src/components/ParamsForm.tsx:54-62`）。**关键是 `buildArgs` 不读它**：拼装层不做枚举校验。你在配置里手写 `think: "看不懂"`，`normalizeThink` 返回 `null`（`src/core/config.ts:97-107`），该项走 `unset`（`src/core/args.ts:533-540`），而不是报错 —— 宁可不传，也不替用户猜一个值。另外运行时还有个同名的 `Capabilities.enumValues(flag)`，它从 help 占位符现解析候选（`src/core/helpProbe.ts:275-279` → `parseEnumValues`，`src/core/helpProbe.ts:166-179`），单测里能直接看到它把 `[on|off|auto]` 解出来（`src/test/helpProbe.test.ts:97`）。

### 3.8 两个逃逸口：`custom_args` 与 `extra_env`

`custom_args` 是「原样追加」，唯一特殊照顾是**放在最后**以便覆盖前面：

```ts
// src/core/args.ts:878-887
  const custom = splitCustomArgs(config.custom_args ?? "");
  if (custom.length > 0) {
    argv.push(...custom);
    steps.push({
      key: "custom_args",
      label: "自定义参数",
      argv: custom,
      reason: "cli",
      note: "用户自定义，原样追加在最后",
    });
```

`splitCustomArgs` 支持单双引号，`--alias "my model"` 不会被切成两半；引号没闭合时剩余内容整体当最后一个参数、**不报错**（`src/core/args.ts:34-37` 的取舍是「尽量让用户启动成功」）。`extra_env` 只在 `src/core/args.ts:212` 被合进返回的 `env`，**不产生任何 step** —— 所以**决策表里看不到它**，要看它得去 CLI 的「附加环境变量」段落（`src/cli.ts:273-276`）或 IPC 预览的 `env` 字段（`src/shared/ipc.ts:200`）。「决策表只覆盖命令行」是这一节最该记住的边界。

### 3.9 single 模式：`main_model` 留空时的兜底

```ts
// src/core/args.ts:353-357
    const mainValue = (config.main_model ?? "") !== "" ? config.main_model : (input.mainModelFile ?? undefined);
    emit({
      key: "main_model",
      label: "主模型",
      candidates: ["-m", "--model"],
```

配置里的 `main_model` **优先**，留空才用调用方解析出的 `mainModelFile`；两者都没有时才 push 告警「single 模式但没有指定主模型」（`src/core/args.ts:364-366`）。调用方那段带存在性检查（`src/core/launcher.ts:276-286`）：`resolveModelFile(config)` 推出路径、`existsSync` 通过才采用，并把实际路径写进 warning（`launcher.ts:281`）—— 所以决策表那行的 `note` 只写「详见告警」，不重复贴长路径。

### 3.10 从 `steps` 到决策表：一一对应的不变式

返回前统一补文案：`steps.map((s) => ({ ...s, reasonLabel: REASON_LABEL[s.reason] }))`（`src/core/args.ts:896`）。主进程转载荷时顺带把每行 argv 格式化成可读文本：

```ts
// src/main/payload.ts:185-188
    steps: prepared.steps.map((step) => ({
      ...step,
      argvText: step.argv.length > 0 ? formatArgv(step.argv) : "",
    })),
```

界面只做三件事：上色、统计、逐行渲染；「实际传入 N 项」只数三种原因：

```tsx
// src/renderer/src/components/DecisionTable.tsx:15-16
/** 这些原因代表"参数确实被传进去了" */
const EMITTED = new Set(["cli", "preload-override", "fallback"]);
```

命令行侧走同一份数据，只是排版不同：`describeSteps` 用 `displayWidth`/`padDisplay` 把中文按 2 列宽算，拼出定宽表格（`src/core/args.ts:115-163`），`cli.ts:284-285` 打印它。**这条不变式可以断言**：把 `steps` 里所有 `argv` 按顺序摊平，应**逐字节等于** `result.argv`。我用 `fixtures/help-b10488.txt` + 与 `src/test/args.test.ts:14-41` 相同的基线配置实跑验证：`argv length 35`、`flat steps length 35`、`bytewise equal: true`（共 49 条决策记录：`cli` 18 / `unset` 25 / `skipped` 6）。换成「router + 预加载 + preset 并集」的形态是 52 条（`cli` 10 / `unset` 28 / `preload-override` 7 / `preset-owned` 1 / `skipped` 6）—— 正好能读出机制：`temperature` 配了 0.7 却因 `preset-owned` 没进 argv，而 `-c` / `-n` / `-t` / 两个 KV 量化 / `--fit-target` / `--load-mode` 这 7 项因预加载例外反而被直传。

## 4. 踩过的坑与设计取舍

**坑 1：命令行会盖掉 preset。** 「参数故意不传」的根因，写在 `src/core/presets.ts:21`：

> · 同一个键 preset 与命令行都给时，命令行优先（实测），所以 preset 里定义过的键命令行不能再传。

**坑 2：预加载的模型反过来不吃 preset。** 同一载体的行为在两个场景下相反，所以规则标在**参数**上而不是开关上（`README.md:166-167`）：例外是「预加载的模型不吃 preset（实测 ctx 被忽略、fit 会把 ctx 压到 4096），此时必须反过来由命令行直传 —— 这条规则用 `preloadBypass` 标在具体参数上，与既有 PS1 脚本逐项对齐」。

**坑 3：`-n` 消失的回归。** 本章最值得记住的 bug（`README.md:170-172`）：

> 这一条是补出来的坑：预设里一旦写了 `n-predict`，而这一项没有 `preloadBypass`，
> 预加载的模型就会被判成"preset 接管"而**不传 `-n`**，于是它以 llama.cpp 默认的"无限"运行
> （改预设那会儿实测复现过一次，命令里确实没有 `-n` 了）。

**坑 4：「关掉」不能靠不传。** `src/core/args.ts:494-495`：「`--jinja` 在 llama.cpp 里默认是【启用】的，界面上关掉必须传 `--no-jinja`，不传等于还开着」。README 的「已知偏离」里同样强调：没有对应形式时要标「版本不支持」+ 告警，「而不是假装关掉了」（`README.md:397-399`）。

**坑 5：不静默降级。** `--fit-target` → `-ngl 99` 改变了「谁来决定分层数」，更糟的写法是干脆不传 `-ngl`（一部分层留在 CPU 上，用户只觉得「变慢了」）。所以它被写成原则（`src/core/args.ts:199-202`）：「**不做静默降级**：任何兼容回退都会同时写进 `steps`（`fallback`）和 `warnings`」。

**坑 6：PowerShell 会吃掉 JSON 的引号。** 所以旧版思考开关宁可走环境变量：`src/core/args.ts:22-24` 记着「Windows 下 PowerShell 把带双引号的 JSON 传给原生 exe 时会把引号剥掉，JSON 就成了非法参数」。这也是 `extra_env` 值得单独建模的理由。

## 6. 自测题

1. `buildArgs` 明知道要传 `--models-preset` 的路径，为什么自己不生成那个临时 ini？这个设计带来什么具体好处？
2. `presetKeys` 为什么是「所有模型段键名的并集」而不是「当前模型段的键」？两者各有什么风险？
3. 预加载模式下为什么 `-c` / `-n` 必须直传，而 `--temp` 不用？给 `--temp` 也加 `preloadBypass` 会怎样？
4. `extra_env` 为什么在决策表里看不到？想让它在界面上也可见，最省事的做法是什么？

<details>
<summary>第 1 题答案</summary>

因为 `buildArgs` 必须是纯函数（`src/core/args.ts:186-188`）：不读文件、不起进程、不访问网络。写临时文件是副作用，一旦放进来就没法「逐字节对拍」。好处：编排集中在 `prepareLaunch`（`src/core/launcher.ts:289-299`）、规则集中在 `buildArgs`，各自可单测；GUI 与 CLI 走同一条链路，「界面里看到的命令 === 实际启动的命令」才可保证（`src/core/launcher.ts:176`）。

</details>

<details>
<summary>第 2 题答案</summary>

并集是**既有行为对齐**（`src/core/presets.ts:108-111`）。并集的风险：某个键只写在模型 A 的预设里，而你跑的是模型 B，命令行就不会传它，可能落回 llama.cpp 默认值；好处是稳定 —— 切模型时命令行不变。单模型段版本（`presetKeysForModel`，`src/core/presets.ts:134-137`）语义更准，但 router 模式下**当前模型运行时可切**（网页左上角），启动时无法预知，而且会与旧脚本行为分叉。

</details>

<details>
<summary>第 3 题答案</summary>

因为预加载的那个模型**不吃 preset**（`src/core/launcher.ts:263-264`），交给 preset 等于没配。`-c` / `-n` / `-t` / KV 量化 / `--fit-target` / `--load-mode` 都标了 `preloadBypass: true`，所以 `owned && !(opts.preloadBypass === true && isPreload)` 不成立，参数继续走到命令行并被标成 `preload-override`（`src/core/args.ts:248-276`）。`--temp` 没标，所以预加载时仍是 `preset-owned`、命令行不传；给它加上 `preloadBypass` 会让 `src/test/args.test.ts:181-182` 的两条断言失败 —— 那两条断言的意义正是「钉住哪些参数该例外」。

</details>

<details>
<summary>第 4 题答案</summary>

因为 `extra_env` 参与的是**环境变量**，而 `steps` 描述的是**命令行参数**：`buildArgs` 只在 `src/core/args.ts:212` 把它合进 `env`，不 push step。它现在只出现在 CLI 的「附加环境变量」段落（`src/cli.ts:273-276`）和 IPC 预览的 `env` 字段（`src/shared/ipc.ts:200`）。最省事的可见化做法：像思考回退里那条 `key: "think_env"` 的 step（`src/core/args.ts:589-597`）一样，返回前给 `env` 的每个键补一条 `argv: []` 的 step，渲染层不用改就能显示 —— `DecisionTable.tsx` 只认 `reasonLabel` / `label` / `argvText` / `note`。

</details>
