# llama-launcher 学习手册

把这个启动器**从外到内讲一遍**的手册。写给会 JS/TS 基础语法、但没写过 Electron、
也没读过上万行项目的开发者。

目标不是让你「会用这个软件」，而是让你能**读懂它、改它、给它加功能** ——
学完第十一章，你会真的动手加一个新参数进来。

> **关于这份手册的可信度**：这个项目本身是 AI 生成的（见仓库根 `README.md` 的
> 「关于 AI 生成」一节）。所以本手册的写法是：**每个结论都指到具体的 `文件:行号`**，
> 代码片段都是从源码里逐字复制的。你可以（也应该）随时翻回源码核对 ——
> 学到的不只是「这里这么写的」，还有「怎么自己确认它确实这么写」。

## 1. 适合谁，要准备什么

**适合**：

- 会写 JS/TS（知道 `interface`、`async/await`、`Array.map` 就够）
- 用过命令行，能跑 `pnpm install`
- 对「命令行参数」「进程」「HTTP 服务」有模糊印象就行，不要求精通

**不需要**：Electron 经验、React 经验、llama.cpp 经验、GPU 编程经验。第一次出现的概念都会解释。

**环境准备**（读代码只需第一条）：

```bash
git clone git@github.com:fengjielin/llama-launcher.git
cd llama-launcher
pnpm install          # 装依赖，约 1~2 分钟
pnpm test             # 192 个单测，全部通过说明环境没问题
pnpm typecheck        # 类型检查，应该 0 错误
```

想**真正启动服务**还需要：一份 llama.cpp 的构建（含 `llama-server.exe`）和一个 `.gguf` 模型。
没有也能学完前十章 —— 每章的代码阅读和练习都不依赖它。

## 4. 边读边跑：五个常用命令

```bash
pnpm test          # 跑全部单测（node src/test/run-tests.ts）
pnpm typecheck     # 类型检查
pnpm args          # 只拼命令行并打印决策表（不起进程）—— 读第 05、06 章时最好用
pnpm cli run       # 直接启动 llama-server（CLI 方式，不经过界面）
pnpm dev           # 打开 Electron 界面（开发模式，改代码会热更新）
```

> 注意脚本名很容易看错：`package.json` 里那个脚本就叫 **`run`**，所以是 `pnpm cli run`
> 或 `pnpm run run`；只写 `pnpm run` 是「列出所有脚本」，什么都不会启动。
> 想确认每个脚本到底跑什么，直接看 `package.json:13-28`。

学第 05、06 章时强烈建议开着 `pnpm args`：你改一处 `llama-launcher.json`，
它就把「每个参数为什么传 / 为什么不传」打给你看，比读代码直观得多。

> 提示：`pnpm args` 里的 `args` 是 `package.json` 里的脚本名。
> 想看它到底跑了什么，打开 `package.json` 的 `scripts` 段，或直接读 `src/cli.ts`。

## 5. 术语速查

第一次遇到不认识的词，先来这里：

| 术语 | 一句话解释 | 详见 |
| --- | --- | --- |
| **llama.cpp / llama-server** | 推理引擎项目 / 它编译出的 OpenAI 兼容 HTTP 服务端 | 01 |
| **GGUF** | 模型文件格式；文件名去掉 `.gguf` 就是服务器眼里的「模型 ID」 | 01 |
| **量化（IQ2_M、Q4_K_M…）** | 压缩权重省显存；数字越小越省、质量越低 | 01 |
| **single / router 模式** | 一个模型写死 `-m` / 一个目录里多个模型热切换 | 01、03 |
| **preset（模型预设）** | 给某个模型覆盖的一组启动参数 | 06 |
| **preload（预加载）** | router 模式下启动即加载的那个模型 | 06 |
| **KV cache** | 注意力缓存，显存大头之一，由 `-c`（上下文长度）决定量级 | 01、07 |
| **-ngl / --fit** | 放到 GPU 上算的层数 / 让 llama.cpp 自己算这个数 | 01、05 |
| **core / main / preload / renderer** | 本项目的四个层，依赖关系是单向的 | 02 |
| **IPC** | Electron 里主进程 ↔ 渲染层的通信通道 | 08 |
| **决策表** | 界面上那张「每个参数为什么传 / 为什么不传」的表 | 05 |

## 6. 学完之后

你可以试着做这些（都是项目里真实存在的下一步方向）：

- 给参数表单加一个新参数（第 11 章就是这个的完整教程）
- 给「环境自检」加一条检查项（第 04 章的 `precheck.ts` 是数据驱动的，加一条很便宜）
- 写一个新的纯函数并给它配单测（第 10 章）
- 理解 `scripts/package.mjs` 之后，尝试改打包输出结构（第 10 章，注意 `.asar` 的坑）

准备好了就从 [01 认识 llama.cpp 与启动器](./01-认识-llama-cpp-与启动器.md) 开始。
