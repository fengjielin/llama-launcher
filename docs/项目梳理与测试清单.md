## 1. 项目定位与运行形态

llama.cpp 启动器，同一套 core 有三种驱动方式：

| 入口 | 命令 | 用途 |
| --- | --- | --- |
| Electron GUI | `pnpm dev` / 打包版 | 桌面主形态：参数表单、决策表、自检、监控、日志 |
| CLI | `node src/cli.ts probe\|args\|run\|init` | 无界面验证 core；也是 GUI 的对拍基准 |
| 测试 | `pnpm test` / `pnpm test:env` | 纯函数 + 临时夹具 + 真机三层 |

设计约束：**同一份配置，CLI 与 GUI 必须产出同一条命令行**。因此参数拼装只允许存在于 `core/args.ts`，
`launcher.ts` 只做编排，`main`/`renderer` 不得二次拼装。

### 2.3 关键链路

1. **配置**：`config.loadConfigFile` → `normalizeConfig`（K 单位、think 联动、显存/上下文告警）→ `discoverModelLayout` 补 `llama_dir/models_dir/preload_model`。
2. **探测**：`launcher.probeServer` 跑 `--version/--help` → `helpProbe.parseHelp` → `createCapabilities`（候选名按优先级回退，旧版本自动降级）。
3. **预设**：配置里的 `presets`（JSON）→ router 渲染临时 ini 传 `--models-preset`；single 用 `presetApply` 把模板填进配置。
4. **拼参数**：`args.buildArgs({config,caps,...})` 产出 `{argv, env, steps, warnings}`；每一步都有 `reason`（cli/preset-owned/preload-override/fallback/unsupported/skipped/unset），决策表直接由它渲染。
5. **启动**：`LlamaServer.start` spawn → `waitForTcp` 判就绪 → 日志经 `LineSplitter`/`classify`/`diagnose`；`MetricsSampler` 采 GPU/CPU/吞吐；`runPrecheck` 做启动前自检。
6. **IPC/UI**：`session` 汇总状态 → `payload` 转 DTO → `main/index` 注册 handler → `preload` 暴露 → `useLauncher` 驱动组件。
7. **CLI**：与 1–5 同一组函数，仅少了 6。

## 7. 后续建议（按性价比）

1. **给 `payload.ts` 加 DTO 快照测试**（纯函数、无依赖，半天内可完成）。
2. **`session` 抽纯函数**：`migrateLegacyPresets`、`resolveStartConfig`、`buildStartError` 三个决策点先覆盖。
3. **环境指纹用例**：env 套件先断言 build/CUDA 主版本/GPU 名/模型文件名，不符时打印差异再 skip，避免“静默跳过”。
4. **CI**：`test` + `typecheck` 必跑，`test:env` 作为可选 job/手动入口。
5. **文档单一来源**：测试数量与模型清单不再手写，或至少在 CI 里比对。
